<objective>
Add the TypeScript domain layer that Phase 11 ingestion can use to validate listing drafts, normalize national Brazil import target data, and upsert listings through the Phase 10 dedupe contract.
</objective>

<threat_model>
Threats:
- T10-02-HIGH-01: An upsert helper that omits `user_id` or conflict keys could create cross-user writes or duplicate listings.
- T10-02-HIGH-02: Accepting arbitrary source names could make later ingestion paths inconsistent or bypass source-specific handling.
- T10-02-MED-01: Treating state/city as Pernambuco-only values would contradict the national product scope.
- T10-02-MED-02: Normalization that drops raw data too aggressively could make Phase 11 source debugging harder.

Mitigations:
- Require `userId`, `source`, `sourceUrl`, and `title` for listing drafts.
- Keep source constants limited to `olx` and `facebook_manual` for MVP.
- Export Brazil state constants and default target examples across multiple states.
- Preserve `rawPayload` on draft records and map it to `raw_payload`.
</threat_model>
