<objective>
Build the auth flow surface: middleware that refreshes sessions on every request and excludes public routes, two auth pages (sign-in, sign-up) styled per UI-SPEC, two Server Actions handling Supabase auth with typed error returns, and the PKCE callback route. This plan delivers AUTH-01, AUTH-02, AUTH-03 end-to-end.

Purpose: A broker can sign up, log in, log out, and have their session reliably persist. The middleware exclusion for /om and /api/track is THE highest-risk decision in Phase 1 — get it wrong and Phase 2/3's public OM page becomes inaccessible.

Output: A working /auth/login + /auth/signup that talks to Supabase Auth, a middleware that protects /dashboard while leaving /om/* alone, and a callback route ready for future OAuth additions.

**Routing decision (deviation from PATTERNS.md):** PATTERNS.md uses the `app/(auth)/login/` route group, which would produce URLs `/login` and `/signup`. We use literal `app/auth/login/` (no route group) so URLs are `/auth/login` and `/auth/signup` — matching the middleware redirect target and the callback's failure redirect. This is the only deviation from PATTERNS.md in this plan.
</objective>

Create `middleware.ts` at the project root (NOT in `app/`) with EXACTLY this content (verbatim from PATTERNS.md lines 51-104, with one addition: authenticated visit to /auth/login redirects to /dashboard per UI-SPEC line 166):

```typescript
import { createServerClient } from '@supabase/ssr'
import { NextResponse, type NextRequest } from 'next/server'

export async function middleware(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request })

  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll()
        },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) =>
            request.cookies.set(name, value)
          )
          supabaseResponse = NextResponse.next({ request })
          cookiesToSet.forEach(({ name, value, options }) =>
            supabaseResponse.cookies.set(name, value, options)
          )
        },
      },
    }
  )

  // CRITICAL: getUser() — never getSession() (silent security hole per CLAUDE.md, SUMMARY.md pitfall #2)
  const {
    data: { user },
  } = await supabase.auth.getUser()

  const isAuthRoute = request.nextUrl.pathname.startsWith('/auth')

  // Unauthenticated user trying to reach a protected route -> /auth/login
  if (!user && !isAuthRoute) {
    const url = request.nextUrl.clone()
    url.pathname = '/auth/login'
    return NextResponse.redirect(url)
  }

  // Authenticated user landing on /auth/login or /auth/signup -> /dashboard
  // (Per UI-SPEC line 166: "Authenticated visit to /auth/login -> /dashboard")
  if (
    user &&
    (request.nextUrl.pathname === '/auth/login' ||
      request.nextUrl.pathname === '/auth/signup')
  ) {
    const url = request.nextUrl.clone()
    url.pathname = '/dashboard'
    return NextResponse.redirect(url)
  }

  return supabaseResponse
}

export const config = {
  matcher: [
    /*
     * Match all request paths EXCEPT:
     * - /om/*           (public OM pages — Phase 2)
     * - /api/track/*    (tracking pixel — Phase 3)
     * - /auth/callback  (PKCE handler must run without our redirect logic)
     * - _next/static, _next/image, favicon, common image files
     */
    '/((?!om|api/track|auth/callback|_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
  ],
}
```

**Why these matcher exclusions are non-negotiable** (CLAUDE.md, SUMMARY.md pitfall #4):
- `/om` — Phase 2's public OM page must work for unauthenticated buyers. If middleware redirects them, they never see the deal.
- `/api/track` — Phase 3's tracking pixel returns a GIF; redirecting it kills tracking.
- `/auth/callback` — Supabase's PKCE flow needs to land on the callback handler unimpeded; do not run the redirect logic on it.

```typescript
'use server'

import { redirect } from 'next/navigation'
import { z } from 'zod'
import { createSupabaseServerClient } from '@/lib/supabase/server'

const LoginSchema = z.object({
  email: z.string().email('Enter a valid email address'),
  password: z.string().min(8, 'Password must be at least 8 characters'),
})

export type LoginState = {
  errors?: {
    email?: string[]
    password?: string[]
    general?: string[]
  }
}

export async function loginAction(
  _prevState: LoginState,
  formData: FormData
): Promise<LoginState> {
  const parsed = LoginSchema.safeParse({
    email: formData.get('email'),
    password: formData.get('password'),
  })

  if (!parsed.success) {
    return { errors: parsed.error.flatten().fieldErrors }
  }

  const supabase = await createSupabaseServerClient()
  const { error } = await supabase.auth.signInWithPassword(parsed.data)

  if (error) {
    // Map Supabase's "Invalid login credentials" message to the broker-facing copy from UI-SPEC line 195.
    return { errors: { general: ['Incorrect email or password'] } }
  }

  redirect('/dashboard')
}
```

**File 1 — `app/auth/signup/actions.ts`** (per PATTERNS.md lines 299-340 + UI-SPEC copy):
```typescript
'use server'

import { redirect } from 'next/navigation'
import { z } from 'zod'
import { createSupabaseServerClient } from '@/lib/supabase/server'

const SignUpSchema = z.object({
  email: z.string().email('Enter a valid email address'),
  password: z.string().min(8, 'Password must be at least 8 characters'),
})

export type SignUpState = {
  errors?: {
    email?: string[]
    password?: string[]
    general?: string[]
  }
}

export async function signUpAction(
  _prevState: SignUpState,
  formData: FormData
): Promise<SignUpState> {
  const parsed = SignUpSchema.safeParse({
    email: formData.get('email'),
    password: formData.get('password'),
  })

  if (!parsed.success) {
    return { errors: parsed.error.flatten().fieldErrors }
  }

  const supabase = await createSupabaseServerClient()
  const { error } = await supabase.auth.signUp({
    email: parsed.data.email,
    password: parsed.data.password,
    options: {
      // Even with email confirmation disabled in dashboard, set this so future re-enable works.
      emailRedirectTo: `${process.env.NEXT_PUBLIC_SITE_URL}/auth/callback`,
    },
  })

  if (error) {
    // Supabase returns "User already registered" or similar — map to the UI-SPEC copy.
    const message = error.message.toLowerCase().includes('already')
```

```typescript
import { NextResponse } from 'next/server'
import { createSupabaseServerClient } from '@/lib/supabase/server'

export async function GET(request: Request) {
  const { searchParams, origin } = new URL(request.url)
  const code = searchParams.get('code')
  const next = searchParams.get('next') ?? '/dashboard'

  if (code) {
    const supabase = await createSupabaseServerClient()
    const { error } = await supabase.auth.exchangeCodeForSession(code)
    if (!error) {
      return NextResponse.redirect(`${origin}${next}`)
    }
  }

  return NextResponse.redirect(`${origin}/auth/login?error=auth_callback_failed`)
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form -> Server Action | Untrusted FormData; CSRF concern (Next.js Server Actions have built-in CSRF protection via origin check) |
| Browser cookie -> Middleware | JWT in cookie; must be validated server-side every request |
| Public route (/om, /api/track) -> No auth | Boundary defined by middleware matcher exclusion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | S (Spoofing) | middleware.ts session check | mitigate | Calls `supabase.auth.getUser()` (network validation of JWT against Supabase Auth) on every request, never `getSession()`. Acceptance criteria greps for absence of `getSession`. SUMMARY.md pitfall #2. |
| T-03-02 | E (Elevation of privilege) | /om/* and /api/track/* | mitigate | Middleware matcher uses negative lookahead `(?!om|api/track|...)` to EXCLUDE these from auth processing — they remain public. Acceptance criteria greps the literal pattern. SUMMARY.md pitfall #4. |
| T-03-03 | T (Tampering) | login/signup form input | mitigate | All inputs validated server-side via zod `safeParse` in the Server Action — client validation is UX only, not security. The schema lives next to the action. STACK.md form-handling rule. |
