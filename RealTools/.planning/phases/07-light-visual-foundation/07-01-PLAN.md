# Plan 07-01: Global Light Theme Foundation

<objective>
Replace the default dark theme foundation with the approved light Nexus-style token system. The root app must load as light by default, global tokens must match the UI-SPEC palette, and shared heading defaults must stop enforcing the v1.1 serif dashboard direction.
</objective>

<requirements_addressed>
UI-05, UI-07
</requirements_addressed>

<truths>
- `app/globals.css` is the source of truth for Phase 7 design tokens.
- `app/layout.tsx` must no longer apply the `dark` class to `<html>` by default.
- Geist is the operational UI font for Phase 7; shared app/card/dialog headings must not default to Cormorant through `font-heading`.
- This plan must not modify Supabase, Resend, tracking, schema, auth behavior, or product actions.
</truths>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-07-01: Visual refactor accidentally touches auth/data/runtime behavior | LOW | Modify only `app/globals.css` and `app/layout.tsx`; verify no `lib/`, `app/api/`, or `supabase/` files are changed by this plan. |
| T-07-02: Root still defaults to dark despite token updates | MEDIUM | Remove `"dark"` from the root html class and verify with `rg 'className=\\{cn\\(\"dark\"|<html[^>]*dark' app components`. |
| T-07-03: Light palette loses accessible focus/invalid visibility | MEDIUM | Preserve tokenized `--ring`, `--destructive`, and `outline-ring/50`; run lint/build and inspect focus classes in later primitive plans. |
</threat_model>
