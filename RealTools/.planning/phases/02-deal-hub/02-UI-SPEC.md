## Page Contracts

### /dashboard — Deal List

Layout: `flex-1 overflow-y-auto bg-zinc-900 p-8`.

Structure (top to bottom):
1. Page header row — `flex items-center justify-between mb-8`
   - Left: "Deals" heading — 20px semibold, `text-zinc-50`
   - Right: "New Deal" button — white accent (`bg-white text-zinc-950 hover:bg-zinc-100`), label "New Deal", Lucide `Plus` icon left of label at `size-4`
2. Deal card grid — `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6`
   - Each card: `bg-zinc-900 border border-zinc-800 rounded-xl` using `<Card>`
   - Card body (`CardContent`): deal title (16px semibold `text-zinc-50`), address (14px `text-zinc-400`), price (14px `text-zinc-400`), status badge
   - Card footer (`CardFooter`): "View Deal" link/button — navigates to `/deals/[id]` — `text-sm text-zinc-400 hover:text-zinc-50`
3. Empty state (when no deals) — centered inside the grid area:
   - Heading: "No deals yet." — 20px semibold, `text-zinc-50`
   - Body: "Create your first deal to get started." — 16px regular, `text-zinc-400`, 8px below heading
   - CTA: "New Deal" button (same style as header button) — 16px margin above

### Deal Create/Edit Modal (Dialog)

Trigger: "New Deal" button (creates), Edit button on Deal Hub (edits).

Dialog structure:
- `DialogHeader`: title "New Deal" (create) or "Edit Deal" (edit) — 20px semibold
- `DialogDescription`: "Fill in the details below." (create) / "Update the deal details." (edit) — 14px `text-zinc-400`
- Form body: `space-y-4`
  - Title field: Label "Deal title" + Input, `placeholder="123 Main St Retail Center"`
  - Address field: Label "Address" + Input, `placeholder="123 Main St, City, State ZIP"`
  - Price field: Label "Asking price" + Input `type="text"`, `placeholder="$4,500,000"`
  - Status field: Label "Status" + `<Select>` — options: Active, Negotiating, Closed — default "Active" on create
  - Description field: Label "Description" + Textarea, `rows={4}`, `placeholder="Describe the property, opportunity, and key highlights…"`
- `DialogFooter`: `flex justify-end gap-3`
  - Cancel button: `variant="ghost"` — label "Cancel", closes modal, no action
  - Submit button: white accent (`bg-white text-zinc-950 hover:bg-zinc-100`) — label "Save Deal" (both create and edit), loading state with `Loader2 animate-spin`

Note: Add `<Select>` to component inventory: `npx shadcn@latest add select`.

Layout: `flex-1 overflow-y-auto bg-zinc-900 p-8`. Single scrollable column, no tabs.

Structure (top to bottom):

**Section 1 — Deal Details (top)**
- Back link: `← Back to Deals` — 14px `text-zinc-400 hover:text-zinc-50`, links to `/dashboard`, 16px below page top
- Header row: `flex items-center justify-between mt-4 mb-6`
  - Left: deal title — 20px semibold `text-zinc-50` + status badge inline right of title (8px gap)
  - Right: "Edit Deal" button — `variant="outline"` zinc style, Lucide `Pencil` icon + label "Edit"
- Metadata block: `grid grid-cols-2 gap-4` inside a Card — address (label + value), price (label + value), description as prose below the grid. Metadata labels 14px `text-zinc-400`, values 16px `text-zinc-50`.

**Separator** (48px vertical margin above and below)

**Section 2 — Notes**
- Section heading row: `flex items-center justify-between mb-4`
  - Left: "Notes" — 16px semibold `text-zinc-50`
  - Right: "Add Note" button — `variant="ghost"` with Lucide `Plus` icon, label "Add Note", 14px `text-zinc-400 hover:text-zinc-50`
- Add note inline form (hidden by default, reveals on "Add Note" click — client component toggle):
  - Textarea: `placeholder="Write a note…"`, `rows={3}`
  - Action row below textarea: "Save" button (white accent, small) + "Cancel" text button, `gap-2`, `justify-end`
- Notes list (reverse chronological):
  - Each note row: `bg-zinc-800/50 rounded-lg px-4 py-3` — note body (16px `text-zinc-50`), timestamp (14px `text-zinc-400`) below body
  - Inline actions on hover: Lucide `Pencil` icon button (edit inline — replaces note body with textarea pre-filled) + Lucide `Trash2` icon button (triggers AlertDialog delete confirmation)
  - Empty state (no notes): "No notes yet." — 14px `text-zinc-400`, centered in section

**Separator** (48px vertical margin above and below)

**Section 3 — Files**
- Section heading row: `flex items-center justify-between mb-4`
  - Left: "Files" — 16px semibold `text-zinc-50`
  - Right: file input trigger — `<label>` styled as button (`variant="ghost"`) wrapping `<input type="file" className="sr-only">`, Lucide `Upload` icon + label "Upload File", 14px `text-zinc-400 hover:text-zinc-50`
- Upload progress: when uploading, show inline text "Uploading…" in 14px `text-zinc-400` with `Loader2 animate-spin` at `size-4`
- File list:
  - Each file row: `flex items-center justify-between bg-zinc-800/50 rounded-lg px-4 py-3` (44px min height)
  - Left: Lucide `FileText` icon (`size-4 text-zinc-400`) + file name (16px `text-zinc-50`), 8px gap
  - Right: "Download" link (opens signed URL in new tab) — Lucide `Download` icon + "Download" label, 14px `text-zinc-400 hover:text-zinc-50`; Lucide `Trash2` icon button for delete (triggers AlertDialog)
  - Empty state (no files): "No files uploaded yet." — 14px `text-zinc-400`, centered in section

Layout: public page, no sidebar, no auth. `min-h-screen bg-white text-zinc-900` (light surface — professional buyer-facing document, NOT dark mode).

Structure (top to bottom):

   - Deal title — 32px semibold `text-zinc-900`, line-height 1.2
   - Address — 18px regular `text-zinc-500`, 8px below title
3. Property details grid: `px-8 py-8 grid grid-cols-2 md:grid-cols-3 gap-6 bg-zinc-50 border-b border-zinc-200`
   - Each detail: label (12px uppercase tracking-wide `text-zinc-400`) + value (20px semibold `text-zinc-900`)

## Interaction Contracts

### Deal Create/Edit Form Validation

Library: react-hook-form + zod. Validation fires on submit (consistent with Phase 1 auth forms).

Schema:
- `title`: required, min 2 characters (`z.string().min(2, "Deal title is required")`)
- `address`: required, min 5 characters (`z.string().min(5, "Address is required")`)
- `price`: required string, min 1 character — stored as text, not parsed as number (`z.string().min(1, "Asking price is required")`)
- `status`: enum `["active", "negotiating", "closed"]`, default `"active"`
- `description`: optional string (`z.string().optional()`)

On invalid submit: `FormMessage` renders inline below each invalid field, `text-sm text-red-500`.
On server error: toast via Sonner — "Failed to save deal. Please try again." — `variant="error"`.
On success (create): toast "Deal created." — modal closes — dashboard revalidates.
On success (edit): toast "Deal updated." — modal closes — Deal Hub revalidates.

### Delete Confirmation Pattern (AlertDialog)

Used for: delete deal, delete note, delete file. Same pattern for all three.

AlertDialog content:
- Title: "Delete [Deal / Note / File]?" — 16px semibold
- Description: context-specific (see Copywriting Contract)
- Footer: Cancel button (`variant="outline"`) + destructive confirm button (`variant="destructive"`, `bg-red-500 hover:bg-red-600 text-white`)
- Confirm button shows loading state (`Loader2 animate-spin`) while server action runs
- On success: toast "Deleted." — list revalidates
- On error: toast "Failed to delete. Please try again."

### Note Inline Edit

Edit mode activates on Pencil icon click. The note body text is replaced with a pre-filled Textarea. "Save" button submits (server action, zod validation: min 1 char). "Cancel" restores read mode without saving. On save success: read mode restores with updated text, toast "Note updated."

### File Upload

File input `accept` attribute: unrestricted (any file type). Max file size enforced server-side: 50MB (Supabase Storage limit). If upload fails size check, toast "File too large. Maximum 50MB." Client shows upload progress via `Loader2` spinner inline in the Files section header — no progress bar for v1.

### Toast Notification Placement

All toasts use Sonner positioned `bottom-right`. Duration: 4000ms. No persistent toasts.

### "View Deal" Card Navigation

Clicking the deal card body (anywhere except the status badge) navigates to `/deals/[id]`. The "View Deal" text in CardFooter is a redundant affordance. Implement as `<Link>` wrapping the card for full-card click, with the "View Deal" label as visual hint.
