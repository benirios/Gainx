<objective>
Refactor deal, buyer, delete, and send-OM dialog/form surfaces into the light UI contract while preserving server action wiring, validation, disabled states, hidden inputs, and toast behavior.
</objective>

<threat_model>
Threats:
- HIGH: Changing hidden input names or action bindings could break create/edit/delete/send workflows.
- HIGH: Changing `buyerIds` serialization could send OMs to the wrong buyers or no buyers.
- MEDIUM: Removing disabled states could allow duplicate submissions.
- MEDIUM: Changing destructive actions could make irreversible operations unclear.

Mitigations:
- Preserve server action imports and `useActionState` calls.
- Preserve hidden inputs `dealId`, `buyerIds`, and `buyerId`.
- Preserve `selectedBuyerIds`, `toggleBuyer`, sent badge logic, disabled submit condition, and toast behavior.
- Preserve delete action calls and existing confirmation copy.
</threat_model>
